# renovatebot/renovate#45152

Minimal reproduction for the Bun artifact manager resolving and writing `.npmrc` in the wrong directory for a workspace package with a root lockfile.

## Setup

This repository contains:

- a root `package.json` defining the `packages/*` workspace
- `packages/app/package.json` depending on [`@jsr/std__semver@1.0.7`](https://npm.jsr.io/@jsr/std__semver), which only exists on the JSR npm-compatibility registry
- a root `bun.lock` generated by Bun 1.3.14
- `renovate.json` providing the scope-to-registry mapping through Renovate's [`npmrc`](https://docs.renovatebot.com/configuration-options/#npmrc) option

There is deliberately no committed `.npmrc`. JSR is public, so the workspace failure can be reproduced without private credentials.

## Current behavior

Renovate's package lookup succeeds because the npm datasource honors `config.npmrc`. It finds the newer JSR package and updates `packages/app/package.json`.

Artifact generation then calls `bun.updateArtifacts(packages/app/package.json)` for the root `bun.lock`. Renovate does not make the configured npmrc available in the root lockfile directory where `bun install` runs, so Bun queries the default npm registry and fails to resolve the package.

This directory mismatch also affects authenticated registries: host-rule credentials written beside the nested package file are invisible to Bun when it runs beside the root lockfile.

Verified against Renovate `main`:

```text
DEBUG: bun.updateArtifacts(packages/app/package.json)
DEBUG: Executing command
       "command": "bun install --ignore-scripts"
DEBUG: rawExec err
       "stderr": "... @jsr/std__semver@1.0.8 failed to resolve"
 WARN: Failed to update lock file
       "lockfile": "bun.lock"
DEBUG: No updated lock files in branch
```

## Expected behavior

Renovate resolves, writes, and restores `.npmrc` relative to the root `bun.lock`, matching the working directory used for `bun install`. The lockfile update then succeeds without committing `.npmrc` or exposing credentials.

Verified against the pull request head:

```text
DEBUG: bun.updateArtifacts(packages/app/package.json)
DEBUG: Writing updated .npmrc file to .npmrc
DEBUG: exec completed
       "stdout": "... 2 packages installed"
       "stderr": "Saved lockfile"
DEBUG: Updated 1 lock files
       "updatedArtifacts": ["bun.lock"]
```

## How to reproduce

```bash
git clone https://github.com/renovatebot/renovate
cd renovate
pnpm install
RENOVATE_TOKEN=<github-token> \
LOG_LEVEL=debug \
RENOVATE_DRY_RUN=full \
RENOVATE_ONBOARDING=false \
RENOVATE_BINARY_SOURCE=global \
pnpm start exKAZUu/renovate-bun-npmrc-repro
```

`RENOVATE_BINARY_SOURCE=global` requires Bun 1.3.14 on `PATH`.

Run against Renovate `main` to reproduce `WARN: Failed to update lock file`. Run again on the pull request branch to see `bun.lock` update successfully.
