# renovatebot/renovate#45152

Minimal reproduction for the `bun` manager ignoring the `npmrc` config option when updating `bun.lock` (artifact generation).

## Setup

This repository contains:

- `package.json` depending on [`@jsr/std__semver@1.0.7`](https://npm.jsr.io/@jsr/std__semver), a package that only exists on the JSR npm-compatibility registry (`https://npm.jsr.io/`), **not** on `registry.npmjs.org`
- `bun.lock` generated by `bun install` (Bun 1.3.14)
- `renovate.json` providing the scope-to-registry mapping via the [`npmrc`](https://docs.renovatebot.com/configuration-options/#npmrc) config option:

  ```json
  {
    "extends": ["config:recommended"],
    "npmrc": "@jsr:registry=https://npm.jsr.io/"
  }
  ```

There is deliberately **no committed `.npmrc` file** — the registry mapping comes only from Renovate config. This mirrors real-world private-registry setups where the npmrc (scope mapping + credentials) is supplied through Renovate config / host rules instead of being committed. A public registry (JSR) is used here so the reproduction needs no credentials: instead of a `401` on the tarball download, the failure shows up as a `404` on package metadata, but the root cause is identical — the configured npmrc is never written for the `bun install` subprocess.

## Current behavior

Renovate's **lookup succeeds** (the npm datasource honors `config.npmrc`, finds `1.0.8` on `npm.jsr.io`) and `package.json` is updated, but the **artifact step fails**: `bun install` runs without the configured npmrc, so Bun queries the default registry (which has no `@jsr` packages) and the branch gets a "Failed to update lock file" artifact error.

Log from a self-hosted run of Renovate `main` (`3a6c7d94b`) against this repository (`LOG_LEVEL=debug`, `RENOVATE_DRY_RUN=full`, `RENOVATE_BINARY_SOURCE=global`, Bun 1.3.14):

## Expected behavior

`bun install` runs with the resolved npmrc (repository `.npmrc` file merged with `config.npmrc` per `npmrcMerge`), so `bun.lock` is updated successfully.

With renovatebot/renovate#45152 applied, the identical run succeeds:

## How to reproduce

```bash
git clone https://github.com/renovatebot/renovate
cd renovate && pnpm install
RENOVATE_TOKEN=<github token> \
LOG_LEVEL=debug \
RENOVATE_DRY_RUN=full \
RENOVATE_ONBOARDING=false \
RENOVATE_BINARY_SOURCE=global \
pnpm start <your fork of this repo>
```

(`RENOVATE_BINARY_SOURCE=global` requires `bun` on `PATH`.)

Run once on `main` (fails with `WARN: Failed to update lock file`), then again on the PR branch (commits `bun.lock`).
